# Pi连分数纪录来源及正确性核查
2026-11-02

结论

本轮追查的是刚才引用的Max Frank计算纪录：前653520000000项普通连分数中报告的最大部分商845188380288。
实际找到的是作者的数据发布、README、计算日志及所用Zuuv程序，未找到对应的期刊证明论文或预印本。
经典连分数数学机制正确；作者报告与日志内部一致；本轮没有独立重跑全部6535.2亿项，公开材料也未提供足以在本轮完成端到端认证的输入π区间与完整前缀证书。
未发现证明本次纪录错误的实际执行反例。下面指出的源码检查不足不能直接当成本次纪录算错的证据。

二、时间与数据范围

作者说明实际计算在2024-10-17至2024-12-08进行，硬件为512GB RAM及两颗AMD EPYC 7543。2025-11-01是OEIS公开报告日期，不应称为计算启动或完成日期。
作者对前300亿项与Fahad旧数据作过对照。实际输出657290105207项，只声明前653520000000项可使用，多出的尾部来自固定迭代大小。
首个输出0而非3是作者披露的问题。源码的磁盘读取只使用小数部分；pi与pi-3的普通连分数除首项外相同，因此这一点可通过替换首项修正，不直接否定后续大部分商。
MD5用于文件一致性，不能单独证明数据对应π。

三、程序的数学思路

它首先需要一份已经算好的高精度π数字文件。日志输入为pi_560b.txt，走十六进制、磁盘模式。
程序把有限数字精确装成一个有限有理数，使用高位部分预测下一段连分数，再利用完整大整数的交叉乘法回代求剩余分数；重复这个过程，并把不同迭代输出到磁盘。

连分数片段[a0;...;an]对应一个二乘二整数矩阵，矩阵乘积记录相邻收敛分数。设当前收敛为pn/qn、前一项为pprev/qprev，后续完整尾项为t，则
  alpha=(pn*t+pprev)/(qn*t+qprev),
  pn*qprev-pprev*qn=±1.
矩阵把许多逐步取整合并为大整数运算；外存使计算规模超过内存。它是有效的批量计算结构，没有凭此证明未来的大部分商一定不断刷新纪录。

四、为什么报告的大部分商确实对应好逼近

令Qn=qn^2 |alpha-pn/qn|，beta=qprev/qn。由上式直接相减，得到
  Qn=1/(t+beta).
若t=A+theta，0<theta<1，且0<=beta<1，那么
  1/(A+2)<Qn<1/A.
对报告的A=845188380288：
  1.1831681827628548643780e-12
    <Qn<
  1.1831681827656546382754e-12.
所以前文所说约1.18e-12的质量量级在数学上成立，前提是报告的连分数项正确。

索引也已核对：作者把首项3作为第1项。纪录位置383059989914对应标准0起始部分商下标383059989913，相关好逼近是前一个收敛，标准下标383059989912。

最大部分商与精确最小Q不是同一统计量。Q还取决于两侧尾项，不能只看最大A就断言已找出整个计算范围里唯一的最小Q。
不过，此次A比此前最大值178811599343大远不止2，故它在首次出现时必定刷新了此前所有收敛分数的Q纪录：
  Q_new<1/A<1/(M+2)<Q_old.
任何非收敛既约分数的Q>=1/2（经典Legendre判据），不影响这个刷新结论。

五、本轮发现的认证边界

1. π输入的边界。
README和日志没有给出pi_560b.txt的来源与严格上下界。Zuuv消费有限数字，而不是直接消费包含π的有理区间。文件转换的正确性与有限输入前缀确属π，属于两件需要分别证明的事。

2. 磁盘模式的安全截断。
source/cruncher.cpp第420-435行先提取高位、预测一段，再固定删去最后10项。Params::TruncateConvergents=10。该固定数值及注释没有附带通用的可证明前缀误差界。
第469-475行回代后主要检查修正分子的符号一致性，没有像RAM路径那样明确回退修正尾项小于1的情况。

仅有修正尾项为正，不足以认证正规连分数前缀。一个精确的小例子是alpha=7/5：若假设前缀[1;1]，按上述矩阵求出的后续尾项为2/3，正但小于1；真实前缀却是[1;2]。
这个例子只证明该单独检查条件不充分。它不是把Zuuv实际喂入7/5后复现的错误，更不是此次π计算的反例；高位预测和删尾可能已经在本次输入上避开这种情况。

3. 全量独立复算。
公开说明的前300亿项交叉验证很有价值，但没有覆盖新增纪录所在的第3830.6亿项。本轮没有下载解压所有巨型输出，也没有重跑几个月量级的原始计算。
因此只能说原始报告有数据、日志与一部分交叉验证支撑，不能说本轮已经独立认证了全部结果。

六、本轮实际复核

从作者日志独立解析54个迭代：项数之和恰为657290105207；各块最大值的最大值恰为845188380288，出现于第32块；作者报告的全局索引落在该块的累计范围内。三者一致。
以1000个随机有限连分数和正有理尾项，逐个用Fraction核查矩阵恒等式、Q公式及1/(A+2)、1/A边界，全部通过。这是数学接口的实现复核，不是原始C++实现或全量π数据复算。
另用精确分数核查上述7/5的必要检查条件反例。

七、对我们研究的意义

可借鉴的部分是整段连分数的整数矩阵处理与精确回代；若移植，应增加有理上下界共同确认前缀的证书。
这项结果通过已知高精度π数字寻找有限好逼近，没有提出保证无限质量趋零的构造，也没有证明π具有统一正下界。
它能说明355/113不是最终最优，不能决定是否存在另一个永久最优分数。

审阅判断：数学机制正确，报告内部可核对内容一致；完整大规模计算的正确性仍未由本轮独立认证。本轮没有足以认定该纪录错误的证据。
